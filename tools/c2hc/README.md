# C to Cool pilot

`make c2hc-test` builds the native host, parses each `tests/*.c` with clang's
JSON AST, writes `.cool` and `.BIN` files under `build/c2hc-test`, and compares
the byte-for-byte stdout of the C executable and native Cool BIN.

Run the translator directly with:

```sh
python3 tools/c2hc/c2hc.py input.c output.cool
```

The translator uses the hermetic headers in `coolc/LibC/include`. Generated programs
include the shared `LibC.cool`; C library calls retain their C names on both the
OS and host. `--libc PATH` sets the include path, `--library` omits the entry call,
and repeatable `--root NAME` selects a function call graph. Multiple C input files
can be linked into one output; file-static names are qualified by translation unit.

Supported constructs include integer, pointer, array, record, union, typedef and
enum types, C record padding, function pointers, variadic functions, static data,
control flow, initializer lists and side-effecting conditional expressions.
Unsupported AST constructs fail with a source location. C `float` is widened to
Cool F64; binary32 storage/layout is not preserved. Record arguments/returns by
value, bit fields, compound literals and computed goto are not supported.

The compiler's postfix cast can reinterpret storage at the destination width.
Integer widening therefore uses typed temporary assignments, keeping adjacent
fields out of narrow loads. Conditional expressions and loop conditions are
lowered to statements when they need side effects.

## stb_truetype bitmap comparison

`make stbtt-test` downloads pinned upstream files into gitignored `vendor/`,
checks their SHA-256 digests, regenerates `coolc/Lib/StbTrueType.cool`, checks it
against the committed copy, and compares six 64×64 bitmaps byte for byte. The
reference is compiled by clang from unchanged upstream `stb_truetype.h`; the
Cool bitmap uses the translated library and native `coolc` host. The test
font is Noto Sans KR (SIL OFL), and the glyphs are `A`, `g`, `Z`, `가`, `나`,
and `한`. Both builds select stb's rasterizer version 1.

The translation input is generated by `stbtt_prepare.py`. Its four asserted
source changes specialize unused CFF/OpenType paths for TrueType: reject fonts
without `glyf`/`loca`, zero the CFF size, and choose TrueType implementations
for glyph boxes and shapes. The upstream header in `vendor/stb` stays
untouched. The platform hook overrides in `stbtt_source.c` use the shared C library. There are no edits to the generated `.cool` file.
The library currently covers the `stbtt_InitFont` and
`stbtt_MakeCodepointBitmap` call graph for TrueType fonts; other stbtt APIs
and CFF fonts have not been verified.
