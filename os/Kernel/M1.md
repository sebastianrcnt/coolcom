# M1 kernel port

The hardware contract and its source references are in [docs/m1-platform.md](../../docs/m1-platform.md). This file records the kernel implementation and hardware checks still needed.

## Build and boot decisions

- `make` uses the checked-in native coolc seed to compile `build/Kernel.BIN`, then produces `build/kernel.Image`: an arm64 Image with a 64-byte header, `ARM\x64` at byte 0x38, flags `0xC` (16 KiB pages, any 2 MiB-aligned base; it was `8`, which said nothing about pages), and `image_size` covering the kernel's BSS and boot stacks. The link base is DRAM + 2 MiB (`0x800200000`); the HolyC module starts at DRAM + 4 MiB (`0x800400000`). The linker uses two passes.
- m1n1 can load at a different 2 MiB-aligned address, so the Image relocates itself exactly, from a table, not by scanning. `tools/binlink.py` records every place the HolyC module holds an absolute address: `IET_ABS_ADDR` offsets, `DATA_HEAP`/`ZEROED_DATA_HEAP` references, the main table entries, and `IET_IMM_I64` imports of addresses (plain-number IMM exports are not addresses and are skipped; an address in a narrower IMM field, an unaligned site or a doubly patched site is a build error). The list is stored in the module as `RELOC_TABLE` (`U64` link-time module base, `U32` count, `U32` pad, then `U32` byte offsets from the module start; 558 sites today). Before touching global data, the primary core in `Boot.S` compares the link-time module base with the real one (`adrp`) and adds the delta to each listed `U64` (MMU off, so 8-byte aligned), cleans and invalidates each patched line with `dc civac` (the MMU-off stores bypass the caches, so a stale cached copy must not survive), then invalidates the I-cache. The assembly (`Boot.S`, `Arch.S`) is position independent: addresses are taken with the `LA` macro (`os/Kernel/Asm.h`, `adrp`+`add`), never `ldr xN, =sym` or `.quad sym`; the pc-relative code is correct at any base, even when the target is a linker-absolute symbol such as `HC_*`.
- `make reloc-check` (part of `make test`) proves the table is complete. `tools/reloc-check.py --elf` fails on any absolute relocation (`R_AARCH64_ABS64/32/16`, `MOVW_UABS`) in the ELF linked with `-q`, i.e. in the assembly. `--compare` links a second Image 4 MiB higher (`IMAGE_BASE=0x800600000`, same HolyC BIN) and requires the two Images to differ exactly at the table sites (and the table header), each by exactly the base delta. This also catches a stray absolute value in initialized data or a missed patch kind. Both checks were confirmed to fail when an `ldr =sym` is added or a site is dropped. `make test` boots the Image at its link address and again with `coolvm --load-offset 0x600000` (4 MiB higher). The alternate Image also passes when loaded 4 MiB and 2 MiB below and 4 MiB above its link base (negative and positive deltas), and a shifted boot with the table emptied fails, so the relocation is exercised.
- `make m1n1-payload` writes `build/m1n1-payload.bin` for real hardware: `m1n1.bin || [chosen.bootargs=<M1N1_BOOTARGS>\n] || t8103-j274.dtb || gzip(kernel.Image) || 8 zero bytes` (docs/m1-platform.md section 2.2). `tools/vendor-m1n1.sh` fetches m1n1 and the Asahi device tree sources at the revisions the platform notes cite into the gitignored `vendor/`, builds m1n1 (Homebrew `llvm@21`/`lld@21`, rustup `rust-src` with `BUILDSTD=1`; about 10 minutes the first time), and runs cpp + `dtc` on `t8103-j274.dts` (Asahi's dtc takes floating-point cells such as `<7.5>`; upstream dtc does not, so they are rewritten as the same IEEE 754 cells). The Image is gzip'd as Asahi ships `Image.gz`: m1n1 then knows the stream's end and stops at the zero word; an uncompressed kernel would have to be last. `tools/m1n1-payload.py` parses the result back as `payload.c` does (m1n1.bin ends at `_payload_start`, the variable, an FDT whose root compatible holds `apple,j274`, a gzip stream that decompresses to the Image with its magic, `image_size` and 16 KiB flag, the terminator). Not yet booted on hardware.
- Both primary and secondary entries test `CurrentEL`. The real m1n1 EL2 handoff clears VHE and interrupt routing, then enters EL1h. coolvm starts at EL1h. The real EL2 path has not been exercised on an M1.
- Early MMU tables use 16 KiB granules: level-2 blocks for MMIO and level-3 pages for DRAM. SoC `0x2_xxxx_xxxx` and the VM finisher region are Device-nGnRnE; DRAM `0x8_0000_0000..0xc_0000_0000` is Normal WB. The tables start at level 2 for `T0SZ=28` (36-bit VA). They cover the full DRAM aperture so the bootloader's chosen Image and DTB positions remain accessible. The allocator uses only FDT `/memory`, skips `/memreserve/` and `/reserved-memory`, and begins after both the Image and DTB.
- `Fdt.HC` reads every 64-bit property as two aligned big-endian 32-bit cells. It obtains RAM ranges, UART/AIC and VM finisher addresses, CPU MPIDRs and release words. The boot console is polled Apple S5L UART; AIC handles peripheral IRQs. CNTV ticks and fast IPIs use FIQ. The FIQ dispatcher reads `IPI_SR_EL1` first, as coolvm requires. SMP writes the FDT release word, cleans it with `dc civac`, and sends `sev`.
- `make run` boots coolvm under a timeout. `make test` boots 2 CPUs with 1 GiB RAM and uses the coolvm finisher exit status. The test requires heap self-tests, scheduler tasks on two cores, timer progress, a fast IPI acknowledgement, and the device tests below. `tools/kernel-test.sh` runs it headless with a fresh 64 KiB disk, a 40 MiB FAT32 disk made by `newfs_msdos` and `mcopy` (mtools), a disposable 64 MiB volume for kernel formatting and repair, a scripted input queue and a 640x480 framebuffer, then `tools/kernel-verify.py` checks the screenshot pixels and both disk files on the host. `make test` boots twice (link address and `--load-offset 0x600000`).

## Devices and drivers

| Driver | File | Where it works | Discovered from |
|---|---|---|---|
| Console registry (`ConsAdd`, `ConsPut`); `Print`, `PutChars` and input echo go to every output | `Console.HC` | everywhere | n/a |
| Apple S5L UART (polled TX) | `Uart.HC` | M1-real and VM | `serial@` node |
| AIC v1 IRQ/FIQ/IPI | `Aic.HC` | M1-real and VM | `interrupt-controller@` node |
| Framebuffer text console, GNU Unifont 8x16 (Hangul and CJK take two cells; `tools/mkfont.py`, `make font`, `Unifont.BIN` after the module via `FontData.S`), scrolling | `Fb.HC`, `Font.HC` | M1-real (m1n1 `simple-framebuffer` in `/chosen`) and VM | `simple-framebuffer` compatible |
| Input FIFO: keyboard and mouse | `Input.HC` | **VM-only** (`coolcom,coolvm-input`); real M1 needs USB HID or SPI keyboard drivers behind the same interface | `coolcom,coolvm-input` compatible, IRQ from `interrupts` |
| virtio-blk (virtio-mmio v2, polled) | `Blk.HC` | **VM-only**; real M1 storage is ANS NVMe behind DART | every `virtio,mmio` node, device ID 2 |
| virtio-net (virtio-mmio v2, polled) and a TCP/IP stack: ARP, IPv4, ICMP, UDP, TCP, DHCP, DNS ([networking](../../docs/networking.md)) | `NetDrv.HC`, `Net*.HC` | **VM-only** NIC (`coolvm --net`, user-mode NAT); the stack is hardware-independent | `virtio,mmio` node with device ID 1 |
| FAT32 file system (TempleOS port) | `Dsk*.HC`, `FileSysFAT.HC` | on any block device | FAT32 boot sector or MBR partition at boot (`DskInit`) |

Nothing is hard-coded: `Fdt.HC` records the framebuffer (`reg`, `width`, `height`, `stride`, `format`), the input node and up to eight virtio-mmio nodes by their `compatible` strings; `Blk.HC` takes device ID 2 and `NetDrv.HC` device ID 1.

- **Framebuffer.** The buffer is outside `/memory` and reserved (`no-map`), but on real hardware it sits inside the DRAM aperture mapped Normal write-back. `FbMapNC` reuses the boot level-3 tables, changes only framebuffer pages to Normal non-cacheable (MAIR attr 2), and uses break-before-make with an inner-shareable TLB invalidation. Pixels are `x8r8g8b8`; other formats leave the console off. `\n \r \b \t` are handled (\b is one column; a wide glyph takes two, like on the UART), wrapping is lazy, and scrolling copies the framebuffer up (reads from non-cacheable memory are slow on real hardware; keep a shadow copy if that matters).
- **Input.** `InputIrq` (AIC IRQ from the FDT, delivered to core 0 via `TARGET_CPU`) drains the FIFO. Key presses become key events (`Key.HC`), the same ones the host terminal produces on the UART: an event is a key code plus `KF_SHIFT/KF_CTRL/KF_ALT`. A character key is its code point with Shift applied (US layout, Caps Lock) and no Shift flag; Ctrl+letter is the lowercase letter with `KF_CTRL`; Enter, Tab, Backspace and Esc are 10, 9, 8, 27; arrows, Home/End, PgUp/PgDn, Insert/Delete and F1..F12 are `KEY_*` codes from `KEY_SPECIAL` (0x110000) and carry Shift. The UART decoder (`KeyUartPoll`, polled by the readers) turns 0x01..0x1A into Ctrl+letter, `\r` into Enter, 0x7F into Backspace, UTF-8 into code points, `ESC [`/`ESC O` sequences (with xterm modifier parameters) into the special keys and ESC+key into Alt+key; a lone ESC becomes Esc after 50 ms without a following byte. Modifier keys alone give no event, and a terminal cannot send Ctrl+H/I/M/[ apart from Backspace/Tab/Enter/Esc. Both feed the physical 256-entry queue; task-bound virtual terminals have independent input queues, fed by Tmux. `GetKey` returns the next event, `GetChar` the next typed character (Ctrl+letter as 1..26), `GetLine` edits a line (arrows, Home/End, Ctrl+A/E, Delete, history) and `GetStr(buf, size)` reads ASCII with Backspace; all block (yield and wait for interrupt). `make key-test` (`tools/key-test.py`) checks that Ctrl+B, Up and Esc give identical events from the window and the UART. Mouse state (`mouse.mx/my` clamped to the screen, `wheel`, `buttons`) is a plain struct. `IrqSet` now sets `TARGET_CPU` to core 0; it wrote 0 before, which routes nowhere.
- **Block.** `BlkCount`, `BlkSectors(dev)`, `BlkRead(dev, lba, cnt, buf)`, `BlkWrite`, `BlkFlush` (512-byte sectors, 0 or a negative `BLK_ERR_*`). The driver negotiates `VERSION_1` and `FLUSH`, uses one 8-entry split queue with the header, data and status descriptors, publishes with `dsb sy` before the doorbell and after seeing the used index, suppresses interrupts and polls with a 2 s timeout under a per-device lock. Buffers are addressed by their identity-mapped address. The model is cache-coherent; a non-coherent DMA device would need cache maintenance on the buffers.
- **FAT32.** TempleOS's FAT32 code and the disk layer under it (drives, block devices, block cache, clusters, directories, `FileRead`/`FileWrite`/`Cd`/`Dir`/`DirMk`) are ported from Aiwnios commit e155e87 (`vendor/aiwnios`, gitignored); RedSea, ATA, CD/DVD, ISO files, RAM disks, compression and the DolDoc output are left out. The bottom calls `BlkRead`/`BlkWrite` of `Blk.HC` (TempleOS's drive-level `BlkRead`/`BlkWrite` are `DrvBlkRead`/`DrvBlkWrite` here). `DskInit` makes every FAT32 volume a drive, `C:` first, from a bare FAT32 boot sector or MBR partitions; each task has a current drive and directory (`CTask.cur_dv/cur_dir`) and starts on the first drive at `/`. There are no exceptions in the kernel yet, so failures print `ERROR:` and return; kernel paths are UTF-8 and VFAT names support 255 UTF-16 code units (including Hangul and surrogate pairs); ASCII names compare case-insensitively. Long-name sequences are validated and span sector/cluster boundaries. Short aliases are unique (`~1`, `~2`, …) and are also accepted for lookup. Dates use `Now`. The file headers list the other changes from TempleOS. `DskCopy.HC` adds recursive `Del`, `Copy`, `Move`, `IsDir` (TempleOS) and `Type` (plain text), `MkDir` and `Rename` (aliases). `FileRead`, `FileWrite`, `Cd`, `Dir`, `DirMk`/`MkDir`, `Del`, `Copy`, `Move`/`Rename` and `Type` are in the generated shell prelude. `DskTools.HC` adds `FatFormat`, `Fsck`, and `DiskInfo`; see [FAT32 tools](../../docs/fat32-tools.md).
- **Tests** (`DevTest.HC`, only with `coolcom.test=1`): the scripted keys and mouse events must produce the line `hiA` and the expected mouse state; sector reads, range errors, a two-sector write, flush and read-back must work and the host checks every sector of the disk file; on the FAT32 disk the kernel reads the host's `HostNote.txt`, writes `FromCoolcom.txt` twice (3000 bytes the second time), makes `Sub` and writes `Sub/Inner.TXT`, lists the root and reads everything back, and afterwards mtools must read the same files on the host and `fsck_msdos -n` must find the volume clean; the tests also round-trip 255-unit Latin and Hangul names, surrogate pairs, colliding aliases and a 20-level Hangul tree. A separate disk is formatted in the kernel, corrupted deliberately (lost allocation, cyclic chain, bad parent, mismatched FAT copies and stale FSInfo), checked read-only, repaired and rechecked. The host validates raw LFN order/checksums/aliases, reads files from both disks with mtools, and runs `fsck_msdos -n` on both. Partial recursive move failures must retain sources. The kernel finally clears the screen and draws four text rows, colour bars and a ramp, which the host compares pixel for pixel against the font.
- **Exception red zone.** The Aiwnios code generator saves callee-saved registers *below* `sp` (`stp x19, x20, [sp, #-16]`, then `sub sp`) and restores them the same way. An interrupt landing between those instructions overwrote them with the exception frame, which showed up as a rare (about 1 in 8) crash in `DevTestBlk` once more code ran between interrupts. `Arch.S` now reserves a 512-byte red zone (`REDZONE`) under the interrupted `sp` before it builds the frame.
- **HolyC stage-0 pitfalls found on the way:** a `$` in a comment broke parsing, and the error was reported at a later `#include` (bisect by truncating at function boundaries).

## TempleOS header and library

- **Header.** `KernelA.HH` is TempleOS's (Aiwnios e155e87, via the compiler's copy `coolc/Frontend/KernelA.HH`), generated by `tools/mkkernela.py`: all its classes and `#define`s and its `extern` prototypes, without the Aiwnios host `import`s and without the classes the kernel lays out itself (`CCPU` in `MultiCore.HC`, the heap's `CHeapCtrl`/`CMemBlk` in `Mem.HC`). Tasks are TempleOS `CTask`s (`Sched.HC`: `next_task`/`last_task` are the core's ring, `task_flags` uses the `TASKf_*` bits, `context_save_area[0]` holds the switched-out stack pointer); `Bool` is TempleOS's `U64`. A kernel definition may differ from its TempleOS prototype (the compiler warns "Fun header ... mismatch"); calls compiled before the definition use the prototype.
- **Library.** Strings, printing, math, hash tables, queues, defines and scanning are TempleOS's code, the same files the compiler is built from (`coolc/Runtime`: `KGlbls`, `KMisc`, `CQue`, `KDataTypes`, `StrA`, `KHashA/B`, `KMath`, `KMathB`, `StrPrint`, `StrB`, `KDefine`, `StrScan`, `QSort`, `NativeExcept` for try/catch/throw). `#define COOLCOM_KERNEL` leaves out, there, what the kernel does its own way (`Sleep`, `SleepUntil`, `IsSilent`). The kernel supplies what Aiwnios's C host does: `KUtils.HC` (memory and string primitives, bit operations, `IsValidPtr`), `KPrint.HC` (`PutS`, where `Print` ends, and `RawPrint`, which formats without the heap for the heap and exception handlers), `KHost.HC` (ticks, `NativeExit` for an uncaught `throw`, stand-ins for DolDoc, pop-ups and sound), `KMathC.HC` (`Exp`, `Ln`, `Pow`, `Sin`, `ATan`, ...; `Sqrt`, `Floor`, `Ceil`, `Round` are instructions in `Arch.S`). From Aiwnios `Src`: `KDate.HC` (dates; `Now` is the host's clock, which coolvm puts in `/chosen` as `coolcom,unix-time` and `coolcom,utc-offset`; a real M1 starts at 1970 until the SMC RTC is read) and, in `Sched.HC`, `TaskValidate`, `Kill`, `Suspend`. `tools/mkprelude.py` fails the build if the kernel and the library define the same function (HolyC would keep the later one without a word).

- **Debugging.** `UAsmARM64.HC` is Aiwnios's ARM64 disassembler, with the printing rewritten (the table names the instruction, operands are decoded from its bits and printed as objdump does, aliases such as `mov`, `cmp`, `cset`, `lsl`, `ubfx`, `mul` and system register names included; checked against `aarch64-elf-objdump -D` over a sample of kernel functions, where only data between functions and vector instructions differ); its opcode table is `Arm64Ops.csv` (made from Aiwnios's `AArch64_ops.csv` by `tools/mkarm64ops.py`, stored in the module by `binlink.py` as `ARM64_OPS`). `KDbg.HC` has TempleOS's `Uf` (kernel functions end at the next kernel symbol, so padding shows as `BAD`; shell functions at their debug info or the next compiled function), `Disas`, `D`/`Dm`/`Da`, `Caller`, `TaskCaller`, `CallerRep` and `Backtrace`, which walk the x29 frame chain and print with `RawPrint`. A fault in shell code prints the backtrace after the error.

- **Power.** `Shutdown` and `Reboot` (`KPower.HC`) flush every block device (`BlkFlush`; the block cache is write-through) and then write coolvm's finisher: `0x5555` powers off, `0x7777` resets, after which coolvm starts again with the same options minus `--input-script`. `Reboot("C:/Kernel.Image")` boots that Image instead (VM-only; `MakeKernel` builds it in the OS, see [kernel rebuild](../../docs/kernel-rebuild.md)). On a real M1 they only flush and halt until the SMC power keys are implemented.

## Shell

`Shell.HC` is a TempleOS-style command line: each line read with `GetStr` is JIT-compiled by the Cool compiler and run at once, and functions and globals persist from line to line (they live in the compiler task's hash table).

- **Compiler.** The checked-in seed `coolc/seed/Compiler.BIN` is embedded in the Image by `Blob.S` (`.incbin`, in the boot stub's read-only data below `MODULE_BASE`; about 570 KiB of room is left, the linker `ASSERT` catches an overflow) and loaded at run time by `BinLoad.HC`, a HolyC port of the loader in `coolc/Host/native.c`: the file is copied to the heap, exports, absolute addresses, data heaps and imports are patched, the I-cache is synced and the 2000-odd initializers run. Imports resolve against a table of kernel routines first (`ShellRtInit`: the services `native.c` provides, e.g. `NativeJitAlloc`/`NativeJitCommit`, `MAlloc`, `Fs`/`SetFs`, `AIWNIOS_SetJmp`/`LongJmp`), then the module's exports; an import nothing defines gets a stub that prints its name and halts the task when called.
- **JIT.** The shell calls the compiler's `ExePutS`, which calls back `ExeCmdLine` (the compiler imports it; the kernel's `ShellExeCmdLine` loops `LexStmt2Bin` + call, like TempleOS). Function code goes to heap memory (identity mapped RWX) through `NativeJitCommit`, which copies it and runs `ArchICacheSync` (`dc cvau`, `dsb ish`, `ic ivau`, `dsb ish`, `isb`). Statement code is not freed, since a global may point at a string constant inside it.
- **Kernel symbols.** `tools/binlink.py` appends a symbol table to the module (`KSYM_TABLE`: every HolyC export and assembly symbol, sorted by address, stored relative to the table so it needs no relocation; `KSym.HC`). Before the first line the shell adds every entry as a `HTT_EXPORT_SYS_SYM` hash entry (`ShellSyms`) and compiles a prelude, `build/ShellPrelude.HH` (embedded by `Blob.S`), which `tools/mkprelude.py` makes from the kernel sources in include order: their `#define`s, classes and unions, an `extern` prototype for every function (assembly `import`s included) and an `extern` for every global variable. In JIT mode `extern` binds each one to the system symbol of that name, so shell code uses any kernel function or global directly; nothing is listed by hand. The prelude (about 150 KB) is stored in the kernel module by `binlink.py` (`SHELL_PRELUDE`); an error in it stops the rest, so the shell would lack everything after it. `FunSegFind`/`StrPrintFunSeg` turn a code address into function+offset from the same table; a fault in shell code reports where it happened that way (`code at StrLen+0x34`); for a function compiled in the shell it looks through the compiler's hash table (`code at F+0x14`).
- **Independent shells.** Each shell loads a separate compiler module and owns its TLS, hash tables, line and exception contexts (`CShell`). x28 points to that shell's TLS and is saved by task switches. Definitions are private to each shell; kernel exports are shared. The compiler layout offsets remain checked by `ShellExeCmdLine`. Shell stacks are 2 MiB with the normal task guard page. The compiler's file imports use the current task's FAT32 drive/directory. Fault/stack-overflow recovery and Ctrl+Alt+C select the affected shell's saved context. A timer scheduling point yields interrupted JIT statements every 10 ms, while kernel/compiler code remains cooperative. See [terminal and Tmux design](../../docs/terminal-multiplexer.md) for routing, memory lifetime and limits.
- **ANSI library.** `Ansi.HC` is the one place that writes escape sequences: cursor (`AnsiCursor(row, col)`, `AnsiHome`, `AnsiUp/Down/Left/Right`, `AnsiCursorHide/Show/Save/Restore`), erase (`AnsiClear`, `AnsiClearLine`, `AnsiClearEol`), attributes (`AnsiReset/Bold/Reverse`, `AnsiFg/Bg/Set` with one color number: 0..15 ANSI, 16..255 xterm palette, `AnsiRgb(r, g, b)`, `ANSI_DEFAULT`), `AnsiAltScreen(on)` and `AnsiTermSize(&rows, &cols)` (the current task's terminal, else the framebuffer, else 24x80). The `...S` variants (`AnsiCursorS`, `AnsiFgS`, `AnsiSetS`, ...) build the sequence into a buffer for drawing a screen in one `Print`. Vim, Tmux, Nyan, `Cls` and the shell line editor (`Key.HC`: cursor-left and erase-to-end-of-line) use it. The framebuffer console (`Fb.HC`) and the task terminals (`Term.HC`) understand SGR 38;5;N / 48;5;N (xterm 256 colors), 38;2;R;G;B / 48;2;R;G;B (truecolor), ESC 7/8 and CSI s/u (save/restore cursor and colors); the framebuffer also honors `CSI ?25 l/h` (hide/show cursor). `make ansi-test` checks the pixels of these and `AnsiTermSize` (30x80 on the 640x480 screen, 29x80 in a Tmux pane).
- **AOT compiling and loading.** `ShellCmp.HC` gives the shell TempleOS's `Cmp`, `ExeFile` and `Load`. `Cmp(src, bin=NULL)` calls the shell compiler's own `Cmp` (AOT, as `coolc` does on the host) and writes the BIN on the FAT32 drive (default `src` with `.BIN`); `#include` names are relative to `src`'s directory, like the host's `chdir`. It returns the error count. (TempleOS's is `Cmp(filename, map_name, out_name)`.) `ExeFile(name)` runs the compiler's `ExeFile`; its statements nest inside the caller's, which keeps its fault context. `Load(bin)` reads the BIN, loads it with `BinLoad` and runs its top-level code. Imports resolve against the shell's system symbols (kernel symbols and earlier `Load`s), then functions defined in the shell. Its exports become system symbols of the shell, so `extern I64 Twice(I64 x);` binds to a loaded `Twice`. An AOT program declares the kernel through `#include "C:/Kernel.HH"`, the shell prelude (`build/ShellPrelude.HH`) that `make run` puts on the disk. A stub for an unresolved import now carries the import's name, so it no longer depends on the task's last-loaded module.
- **Syntax highlighting.** The formatter's tokenizer is a shared library, `coolc/Fmt/HCTok.HC` (`HCTNext` splits a line into tokens and keeps the block-comment/string state for the next line in a `CHCTok`; plain HolyC, so it builds into the native formatter and, included by `Kernel.HC`, into the kernel; `tools/hcfmt.sh --selftest` and `make fmt-check` prove the formatter's output is unchanged). `Syntax.HC` maps a file extension to rules (`SynLang`: Cool `.HC/.HH` with the shared tokenizer, Warm `.aum/.aui` with its own `--`/`"""` lexer, else plain text), turns a line into a highlight group per byte (`SynLine`) and looks up each Cool identifier in the current shell compiler's hash table (`SynSymKind`: function, type, global, `#define`; an unknown name followed by `(` still reads as a call). Colors are the table `syn_color[SYN_G_*]` (Ansi.HC color numbers); Vim also takes `:hi comment 2` and `:set ft=cool|warm|text`. Vim keeps the lexer state of the first visible line while the text is unchanged. `make syntax-test` checks it on the UART stream and the framebuffer.
- **AOT compiling and loading.** `ShellCmp.HC` gives the shell TempleOS's `Cmp`, `ExeFile` and `Load`. `Cmp(src, bin=NULL)` calls the shell compiler's own `Cmp` (AOT, as `coolc` does on the host) and writes the BIN on the FAT32 drive (default `src` with `.BIN`); `#include` names are relative to `src`'s directory, like the host's `chdir`. It returns the error count. (TempleOS's is `Cmp(filename, map_name, out_name)`.) `ExeFile(name)` runs the compiler's `ExeFile`; its statements nest inside the caller's, which keeps its fault context. `Load(bin)` reads the BIN, loads it with `BinLoad` and runs its top-level code. Imports resolve against the shell's system symbols (kernel symbols and earlier `Load`s), then functions defined in the shell. Its exports become system symbols of the shell, so `extern I64 Twice(I64 x);` binds to a loaded `Twice`. An AOT program declares the kernel through `#include "C:/Kernel.HH"`, the shell prelude (`build/ShellPrelude.HH`) that `make run` puts on the disk. `make run` also puts the compiler sources in `C:/Compiler`, and `Cmp("C:/Compiler/Native.HC")` rebuilds the seed byte for byte; `make selfhost-test` (in `make test`, about 3 s) checks that and a `Cmp`/`Load`/`ExeFile` round trip, driven by `C:/Init.HC`. A stub for an unresolved import now carries the import's name, so it no longer depends on the task's last-loaded module.
- **Hangul input.** `Ime.HC`: 2-beolsik composition for the VM window's keyboard (`Input.HC` calls it; the UART is untouched, the host terminal composes there). Shift+Space, the Hangul key, or Right Alt pressed and released alone toggles it (`Ime(TRUE/FALSE)`, `ime_on`). With it on the letter keys type jamo (Shift: ㅃㅉㄸㄲㅆㅒㅖ) and the syllable being composed is rewritten on screen at every key: the IME queues a Backspace and the new text, which the line editor, the shell and Vim's insert mode already handle, so nothing else knows about it. The usual automaton: a consonant after a syllable becomes its final if it can (ㄳ ㄵ ㄶ ㄺ ㄻ ㄼ ㄽ ㄾ ㄿ ㅀ ㅄ clusters), a vowel after a final takes it (or the cluster's last consonant) as the next initial, ㅗ/ㅜ/ㅡ combine with the vowels that make ㅘ ㅙ ㅚ ㅝ ㅞ ㅟ ㅢ, Backspace takes off the last jamo. Any other key ends the syllable. Vim's status line shows `[한]` while it is on. `make ime-test` types words with it and checks the shell's output, Vim's saved file and the screen.
- **Text tools.** `Find("text", mask)` (recursive, prints `file,line: text`), `Less("file")` (pager: paging, `/` search, UTF-8 width, wraps by terminal columns), `Man("Name")` (opens Vim, or Less over 128 KiB, at the definition: a symbol the shell compiled has its file and line in the compiler's hash entry, `src_link`; kernel symbols come from the prelude, so their source is found by the shape of a definition in `C:/Kernel`, where `tools/disk-files.sh` puts `os/Kernel/*` and `coolc/Runtime/*`), `Diff("a", "b")` (report; `TRUE` as third argument merges; port of Aiwnios `Diff.HC`) and `HexDump("file")` are in `os/Disk/` (see its README). `make text-test` runs them.
- **Tmux.** `os/Disk/Tmux.HC` runs independent shells in ANSI virtual terminals (`Term.HC`). Ctrl+B followed by `%`/`"` splits, arrows/`o` selects a pane, `c` creates a window, `n`/`p` changes windows, `x` closes a pane and `d` detaches. `Tmux;` reattaches the caller's session. Input scripts and framebuffer pixel verification are part of `make test`.
- **Test.** After the `hiA` line the input script types `I64 Sq(I64 x) { return x * x; }` and `Print("%d\n", Sq(7));` (generated by `tools/kernel-verify.py`); `DevTestShell` runs the shell for two lines and then evaluates `Sq(7);` itself, which must return 49, and `tools/kernel-test.sh` requires a line `49` in the output. Without `coolcom.test=1` the kernel starts the shell on core 0 after the demo and it reads lines forever.
- **Compile errors.** Every compile error prints `ERROR: <message>`, the file and line (not for a typed line), the source line and a caret, in every shell (Tmux panes included) and through `ExeFile`, `#include` and `Cmp`. Three silent cases were fixed in the compiler: an empty expression where one is required (`I64 bad = ;`, `if () 1;`, the bare `throw('Compiler')` after `PrsExpression`/`LexExpression2Bin` in `PrsVar.HC`/`PrsStmt.HC`), a missing `#include` file (it was included as empty; now `File not found`, and `#include "X"` defaults to `.HC`, not TempleOS's `.HC.Z`; the dead `#include "Headers.HH"` in `KernelA.HH` was removed), and an error on a token at the end of a line was reported on the next line with an empty source line (`Lex` reads one character past each token; `LexPutPos` now steps back). `make test` checks a typed line (kernel-test), a Tmux pane (tmux-test) and `ExeFile` (selfhost-test).
- The US key map lacked `%`, so Shift+5 through Shift+- gave the symbol of the next key and Shift+= gave nothing; fixed in `KbdMapInit`.

## M1 hardware checks

1. Boot `build/m1n1-payload.bin` (m1n1 stage 2 with the Asahi `t8103-j274.dtb`; `make m1n1-payload`), or the Image through m1n1 `linux.py`. Verify the image relocation and FDT memory reservations against a real 8 or 16 GiB memory map.
2. Verify that dropping from m1n1's VHE EL2 state to EL1 delivers CNTV FIQs directly. If `HCR_EL2.FMO` or `VM_TMR_FIQ_ENA_EL2` needs different setup, adjust the EL2 handoff. coolvm cannot validate this path.
3. Check `ID_AA64MMFR0_EL1` for 16 KiB page support, and verify page-table attributes with the actual Apple bus. The current broad DRAM mapping includes carve-outs as Normal, although the allocator never touches them; refine mappings from the FDT before using framebuffer or DMA devices.
4. Confirm UART0 availability and baud after m1n1 shuts down USB. A physical VDM serial cable or m1n1 HV guest is needed for console output on a Mac mini.
5. Confirm m1n1's CPU release words and cache maintenance on both Icestorm and Firestorm cores. The coolvm test exercises only E0 and E1.
6. The real SMC power-off protocol is not implemented. The finisher is selected only when FDT root compatibility starts with `coolcom,coolvm`.
7. The framebuffer console assumes m1n1's `simple-framebuffer` (x8r8g8b8 from `/chosen`) and the non-cacheable remap above; verify on hardware that the remap works and scrolling speed is acceptable. Keyboard and storage need real drivers (USB HID via the DWC3/Type-C stack or the SPI keyboard, and ANS NVMe with DART); the VM-only input and virtio-blk drivers are not present on an M1.

## Memory safety (memsafe)

- The heap keeps a 16-byte front canary and an 8-byte tail canary immediately after the requested bytes, including odd and zero sizes. `Free`, `ReAlloc`, `MSize`, `HeapCheck` and `HeapStats` check them. A damaged block is reported with its payload address, requested size and allocation return PC, and is not freed or resized. `MSize` now returns the requested usable size; allocator padding is not usable. Reallocation preserves the original allocation PC. Diagnostics avoid heap allocation while the heap lock is held.
- Every spawned task has a page-aligned, unmapped 16 KiB page below its downward-growing stack. The allocator ownership pointer is separate from the usable stack bounds. Reaping restores the mapping before freeing the backing block. Adam and the secondary boot tasks also have static guards. Synchronous exceptions run on a separate 16 KiB stack per core and preserve the interrupted SP. Shell recovery restores the pre-statement interrupt mask as well as SP, including when an interrupt entry itself hits the guard. An overflow prints `stack overflow, task <name>`; a shell statement returns through its saved context to the prompt, and another spawned task exits through the scheduler. A boot task overflow is fatal after diagnosis. Compiler-line overflows can use the saved line context once the shell is initialized.
- `Boot.S` builds all 512 DRAM level-3 tables before enabling the MMU (8 MiB reserved in the Image footprint). Assembly text/rodata and the page-aligned HolyC code range are EL1 read-only. `binlink.py` starts the initializer table and globals on the following page; relocation still finishes before protection is enabled. Heap memory, loaded compiler modules and shell JIT code remain writable/executable. Framebuffer remapping and task guards reuse these tables; TLB invalidations are broadcast to the inner-shareable domain.
- `make test` includes one scripted shell regression: corrupt a 13-byte allocation's tail, recurse with 1 KiB frames into the guard both normally and with interrupts masked, write to `StrLen`, then evaluate `Sq(9)` and require `MEMSAFE RECOVERED 81`. The host requires all three diagnostics and runs the regression at both the linked and relocated load addresses. Boot heap tests additionally cover front canaries, `ReAlloc` rejection and whole-heap scanning. Existing compiler loading, JIT, Vim, disk and framebuffer tests remain enabled.
- These are boundary detectors, not isolation from arbitrary kernel pointers. A sufficiently large stack decrement can jump over a single guard page; generated code does not yet probe every crossed page. Real M1 permission faults and broadcast TLB maintenance still need hardware validation.
