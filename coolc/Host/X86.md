# x86-64 BIN runner on macOS

`make build/coolc build/coolc-x86_64 seed` builds the ARM compiler host, the
x86 runner, and the reproducible ARM compiler seed. Rosetta 2 must be installed
on Apple Silicon. No x86 kernel or guest OS is needed.

```sh
build/coolc --target x86_64 example.cool build/example.BIN
build/coolc-x86_64 --run build/example.BIN
build/coolc-x86_64 --probe build/example.BIN ExportedZeroArgumentProbe
```

The default target is `arm64`; `--target arm64` selects it explicitly. The BIN
layout stays unchanged: its existing signature at offset 4 is `ARM` or `X86`.
Each runner checks it before executing a module.

The x86 backend uses Aiwnios's HolyC ABI: stack arguments, callee cleanup for
fixed signatures, caller cleanup for varargs, and floating results in RAX
(also XMM0). `x86.S` bridges that ABI to macOS services, preserves the Cool
integer and SSE registers, and changes GS base at each boundary. Cool uses
`GS:[0]` for Fs and `GS:[8]` for Gs, as decided in `docs/x86-64.md`. Native
macOS services use their original TSD base. A temporary pthread key identifies
that base without embedding a private pthread layout offset. The runner is
single-threaded; it does not implement the kernel's per-core architecture layer.

Darwin's TSD base convention follows Apple's
[libpthread `_pthread_set_self`](https://github.com/apple-oss-distributions/libpthread/blob/main/src/pthread.c).
The runner uses the x86 `thread_fast_set_cthread_self` machine-dependent syscall
to switch it; the executable is built with `clang -arch x86_64` and runs through
Rosetta on an ARM Mac.

## Verification and limits

`make codegen-test` compiles drivers for all 24 `coolc/tests/codegen` units
and runs 1,703 function probes on ARM and x86, comparing stdout byte for byte,
including F64 bit patterns and hashes of modified memory. It also asserts the
unsigned 64-bit FNV result and atomic increments independently, checks the GS
slots, rejects mismatched BINs and unknown targets, and verifies that the default
compiler target produces the same BIN as explicit `--target arm64`.
`make test` includes this check and consequently needs Rosetta on Apple Silicon.
Use `python3 tools/native/codegen.py --suite T17SpillFloat` to diagnose one unit.

These are executable probes of the safe entry points, not every possible input
or every function in the corpus. Pointer arguments receive bounded, initialized
buffers; functions requiring valid function pointers, pointer-to-pointer graphs,
aggregate value parameters or arbitrary addresses are not automatically called.
T19's R31 dereferences its integer argument as an address, and R32 measures an
absolute address, so neither is an execution comparison. T24's Y7 and Y9 abort
in the existing ARM backend when taking the address of an aggregate call;
the generated T24 copy omits those two functions. Aggregate value arguments and
returns (Y1/Y2/Y8/Y10/Y11) remain unverified. T24's external arrays receive direct
storage definitions in the driver: the existing frontend does not turn a later
uninitialized array redeclaration of an extern into a storage definition.
The original corpus is unchanged; generated drivers and logs live in
`build/codegen/`.

The x86 runner supports `--run` and zero-argument `--probe`. Cross compilation
uses the ARM host and seed; x86 JIT, compiler self-hosting, formatting, kernel
boot and architecture services are not implemented by this runner. The source
assembler/disassembler still targets ARM; `--target x86_64` rejects inline
assembly instead of emitting ARM instructions into an x86 BIN. The x86 machine
instruction encoders needed by the IR backend are part of the Cool port. Warm task
spawning/abort is explicitly rejected because its callbacks need a threaded x86
ABI and per-thread GS state. File/network/time imports use the native ABI bridge.
Privileged instructions and kernel per-core setup require the future x86 kernel
architecture layer, which is outside this change.

The port includes the owned ARM frontend's aggregate-copy extension and fixes
Aiwnios's unsigned variable shift register, floating shifts/dual-bank return
convention, and speculative LEA retry that caused exponential compilation time.
Scalar assignment/increment operands follow the ARM port's evaluation order.
The ARM parity checks exposed 32-bit widening multiply instructions in 64-bit
unsigned arithmetic and a locked postfix increment modifying its address
register and storing the old value. The ARM fixes also use a distinct exclusive
store status register and the correct 32-bit store width. Floating shifts now
use the assigned count register and move the resulting bits back to SSE/FP.
Return IR preserves the declared scalar return type. These changes require
regenerating the ARM seed with `make seed` (gen2 must equal gen3).
The larger compiler blob also requires ARM boot's page-table address load to
use ADRP+ADD instead of ADR's ±1 MiB range.
ARM code-buffer allocation now reserves space per IR node for the extra
instructions needed once addresses resolve. The old fixed 1 KiB margin was
too small for the large x86 emitter function and could truncate the native
commit or overrun the OS heap during compiler self-build.
